## How to size a pass

The old rule was “one branch, one deploy, one bet.” It came from Pass 1, which shipped the gather lock and the invitation cut in the same commit and then needed a full RCA to work out which one caused the 3/15.

**1-A disproved the rule as written.** It bundled *five* fixes and every one was attributed cleanly — because each had its own runtime signal, checked at **step 5** before a single occupancy number was read. Deleting the lock, the invitation, the identity seed, the travel anchor and the ritual gate all show up in different places.

The real rule:

> **Bundle freely when each fix has an independent observable. Serialize only when two fixes move the same number.**

Corollaries:

- Before bundling, name the observable for each fix and the step you can read it at. No observable → it does not go in the run.
- Gather and sofa were separated because both move **occupancy**. That held up: chat was tested as the remover on `20260828-1` and cleared, so they are two bugs and the split was right. Re-check the assumption whenever two deferred items touch the same metric.
- A run is not “one bet.” It is “one bet **per shared number**.”

This is what makes the step-5 gate worth more than the run: it converts a 27-hour experiment into a ten-minute one for anything with an early observable.
