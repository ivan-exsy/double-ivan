## 1. Problem statement (narrow)

Two failure classes look similar in logs but are **not** the same bug:

| Class | Definition | Player impact | Status after `6057e10d` |
|-------|------------|---------------|-------------------------|
| **D — Display honesty** | Act / API text names place A while body or sealed plan is B | Status bar lies or double-names places | **Largely fixed (global)** — prefer-emit + `conflicting_place` / travel-safe emit |
| **P — Destination pick** | Planner **seals** `act_address` (and moves body) to sector B while act intent names sector A | Character goes to the wrong place; rewrite may then *honestly* say “walking to B” | **Still open for non-Hobbs / non-Vince cases** |

This inquiry’s primary question:

> Across the full pipeline from movement **intent generation** to **execution**, why does the system sometimes **pick and seal** Johnson Park (or another sector) when the act’s intent destination is elsewhere?

Secondary (do not confuse with P): pathfinding `CRITICAL PATH ERROR` + 1-tile fallback when already at target — **execution noise**, not destination authority.

## 5. Why P1 does not stop Market / Oak Hill → Park

`_named_destination_protects_address(act, address)` returns true only when:

1. Act is travel-like, **and**
2. Act text names the sector of the **current** `address`.

It is a **keep-if-already-correct** guard, not a **pin-to-named-intent** guard.

Therefore Class P still happens when any of these win:

1. **First resolve lands on Park** (LLM / filtered tree / sticky contract / weak literal pin) while text says Market or Oak Hill — protect never fires (text does not name Park).
2. **First resolve lands on Market/Oak Hill**, then whitelist rejects `activity_type`, and protect **fails the name match** (e.g. sector `The Willows Market and Pharmacy` vs act `Willows Market` — tokenization edge), then Tier-2 remaps to Park.
3. **Inherit / contract sticky** seals a prior Park leaf despite new travel label (detach should reduce this; verify on residual rows).
4. **activity_type still wrong** for non-stretch cases (coerce only covers travel + light stretch patterns).

`20260729-1` API rows with `conflicting_place` are consistent with (1) or (2): sealed Park, raw intent elsewhere, emit aligned to Park.

## 6. Working hypotheses (ranked for inquiry)

Order = most likely given current evidence + prior RCA; each needs a **prove/disprove** experiment (no keyword patchwork).

### H1 — Literal named-destination grounding loses to LLM / tree (primary open)

**Claim:** `_find_literal_sector_in_text` / typed grounding does not reliably bind “Willows Market” / “Oak Hill College library” to the correct sector before LLM pick; Park is chosen as a high-scoring or nearest fallback.

**Prove:** On residual steps, soak/resolver logs for `literal` / `pinned_sector` / `generate_action_location` choice order. Compare act string → expected sector → first candidate vs sealed.

**Fix direction (if proven):** Strengthen early pin (alias table for known venues; require travel acts that name a known sector to resolve inside that sector). Align with SOT §3.3 spirit: place claim owns destination. Document; avoid per-verb keyword lists.

### H2 — Whitelist cascade still remaps after a correct first pick (RC2 remainder)

**Claim:** Market/Oak Hill resolves correctly, then `activity_type ∉ whitelist` and named-dest protect fails → Tier-2 Park.

**Prove:** Grep soak for `forbidden-cascade Tier-2` and `POST-VALIDATE keep named dest` on the same personas/steps as residual assigns. Capture `activity_type` on those rows.

**Fix direction:** P2-SOT-2 from prior RCA — when act claims sector A and remap target is unrelated sector B, do not cascade across sectors (remap within claim / re-resolve under claim / keep prior legal address). Staff/privacy/affordance stay unconditional.

### H3 — activity_type mistag beyond travel/stretch coerce

**Claim:** Rows still enter resolve as `exercise` (or other incompatible types) for named travel that coerce regex/prompts miss.

**Prove:** Decomp counters + per-assign `activity_type` on residual Park seals.

**Fix direction:** Extend coerce only with clear travel/place-claim rules; prefer H1/H2 structural fix over endless tag patches.

### H4 — Contract sticky / inherit re-seals Park

**Claim:** New act “walking to Oak Hill” reuses prior `resolved_address` at Park via semantic sticky match.

**Prove:** ACTION CONTRACT short-circuit logs; `_travel_named_destination_mismatch` reject rate on residual steps.

**Fix direction:** Harden mismatch reject; never sticky-cross-sector on travel-like labels.

### H5 — Display-only confusion (control)

**Claim:** Some “failures” are only Class D.  
**Status:** Disproven for the Table in §2.3 — those rows have Park as sealed addr, not merely bad copy.

### Non-hypothesis (exclude from Class P)

- Pathfinding CRITICAL fallback when already at tile.
- Presence `@` suffix showing current sector while travelling (SOT §5.4 presence vs intent) — can look noisy but is not wrong sealed dest if `act_address` matches intent.
