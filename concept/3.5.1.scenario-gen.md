### **Global Scenario Events**

To inject world-altering changes (e.g., "sun blast" causing deaths after 10 min), extend the existing observation system into **Global Scenario Events**. This keeps it simple: treat globals as a special observation type that the backend processes to mutate shared simulation state (e.g., environment variables, agent-wide effects). Propagation happens via Supabase Realtime (for persistence) + WebSocket (for live updates), with Phaser handling visuals/behaviors.

#### Core Principles
- **Frontend**: Submit via POST to `/api/simulations/{simCode}/observations` (reuse `reportObservation`), but with `type: 'global'` and structured `details` (e.g., `{ effect: 'sun_blast', duration: 600, impact: 'death' }`).
- **Backend (reverie.py)**: On receipt, inject into a global state (e.g., `scenario_globals` dict in sim context). For "sun blast": Set a countdown timer; at expiry, apply effects (e.g., kill agents via `persona_status: 'dead'`). Broadcast via WebSocket with `type: 'global_update'`.
- **Simulation Impact**: Globals override agent logic (e.g., force all agents to "panic" mode, alter environment like sky tint). Persist in Supabase `simulations` table (new `scenario_globals` JSONB column).
- **Frontend Visualization**: In `MainScene.ts`, listen for `global_update` via `useRealtime.ts`; apply Phaser effects (e.g., red overlay, agent animations). For playback, query historical globals from Supabase.
- **Safety**: Rate-limit submissions (1/min), validate effects (whitelist: 'sun_blast', 'flood', etc.), RLS for auth.

This reuses 80% of existing infra (observations API, WS, Supabase), adds ~100 LOC total, and scales to MVP (e.g., 3-5 predefined effects).
