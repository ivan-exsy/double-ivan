# Supabase Playback Debugging Guide

## Overview

This guide provides a systematic approach to debug simulation playback issues. The data flows through 5 layers:

```
┌─────────────────────────────────────────────────────────────────────────┐
│  LAYER 1: BACKEND SIMULATION (reverie.py)                               │
│  → Generates AI decisions, paths, movement intents                      │
│  → Writes to Supabase personas_coords with movement JSONB               │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│  LAYER 2: SUPABASE DATABASE                                             │
│  → personas_coords table stores: x, y, step, movement JSONB             │
│  → movement JSONB contains: target_zone, path, speed_multiplier         │
│  → RPCs: get_step_positions, get_all_step_positions                     │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│  LAYER 3: API GATEWAY (FastAPI :8001)                                   │
│  → Calls Supabase RPCs, transforms data to JSON format                  │
│  → Falls back to JSON files if Supabase fails/empty                     │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│  LAYER 4: FRONTEND DATA LAYER (hooks/lib)                               │
│  → Receives API response, converts tiles→pixels (×32+16)                │
│  → Stores in Redux state, triggers animations                           │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─────────────────────────────────────────────────────────────────────────┐
│  LAYER 5: PHASER VISUALIZATION                                          │
│  → AnimationManager executes path tweens                                │
│  → MainScene renders sprites at positions                               │
└─────────────────────────────────────────────────────────────────────────┘
```

### *✅ 1.2.x ISSUE IDENTIFIED AND FIXED: Frontend Headless Verification*

The frontend returned HTTP 500 errors for new simulations (e.g., `20260113-5`) because they were not registered in the `double.simulations` table. The backend forked from `base_family_sim` without creating a baseline entry in Supabase, blocking frontend SSR. Additionally, the headless visualization read step data directly from JSON files, bypassing Supabase as the single source of truth (SOT).

**✅ Fixes Applied**  
1. **Register Baseline Simulation**: Added `base_family_sim` to `double.simulations` as a baseline (`is_baseline=true`, `fork_depth=0`) using a one-time SQL script in Supabase. This enables the `fork_simulation` RPC to register new simulations with proper parent links, resolving frontend query failures.  
2. **Supabase-First Data Fetch in Headless**: Updated `reverie/backend_server/headless_visualization.py` to fetch step data via the API Gateway (`/api/simulations/{sim}/step/{N}`), which invokes the `get_step_positions` RPC on `personas_coords`. JSON fallback is used only on failure, ensuring Supabase SOT compliance.  
3. **Race Condition Handling**: Verified pre-existing guards for hook execution and HTTP error handling prevent timeouts and ensure reliable observations.

*Impact*: New simulations now fork successfully without 500 errors. Headless uses Supabase positions via API/RPC, closing the feedback loop: backend plans → Supabase writes → API fetch → frontend execution (A*/tweens) → observations → replans.

#### *VERIFICATION RESULTS: Headless Loop Enabled*

The data flow now fully integrates Supabase: Backend writes to `personas_coords` (SOT) with JSON backup; headless fetches via API (RPC); frontend queries simulations table, loads without errors, executes movements, and generates reports; backend processes observations for replans. 
For new sim `20260113-5` (3 steps), verification confirmed successful forking/registration, page loads, step data retrieval from Supabase, sprite creation/tween completion, 30+ reports triggering replans/chats, and loop closure on deviations. Performance: Steps take 45-95s (headless dominant); minor optimizations needed for slow retrievals. Edge cases like invalid reports are filtered, and all features (A*, observations, chats, replans) function cleanly. No explicit fork logs, but verifiable via Supabase queries.

## ✅ **Phase 4.A: Coordinate system mismatch**

Diagnosis: *Primary blocker is coordinate system mismatch*

Backend A* → generates pixel paths ignoring collision layer
Frontend A* → validates against tilemap collisions → finds blocked tiles → BridgeFailure

Backend paths reference walkable zones but don't account for `interiors_pt3` tileset collision data. Frontend tries to connect sprites to invalid waypoints, causing wall-walking and teleports.

### *Fixes*

- [x] ***BACKEND*-P0: Intent-Only Path Mode (Phase 10.8)** `reverie.py:86-93, 1780-1845`
  - Added `BACKEND_INTENT_ONLY_PATH=true` env var (default: enabled)
  - Backend writes `path: [start_position]` + `planned_pos` (target hint)
  - Frontend computes A* on collision layer — fixes wall-walking
  - `partial_state.remaining_path` cleared in intent-only mode

- [x] **<FRONTEND>-P2: Supabase Collision Debug Visualization** `MainScene.ts`, `CollisionChunkManager.ts`
  - Added blue overlay for Supabase chunk collisions (key "8")
  - Red = Tiled JSON collisions, Blue = Supabase chunks
  - If both overlap (purple), data is synchronized correctly
  - Added `getLoadedChunksForDebug()` and `getDebugInfo()` methods

- [x] **<FRONTEND>-P0: Wall-Walking Bug Fix (A*-POCKET)** `AnimationManager.ts`
  - Root cause: destination tile walkable but surrounded by colliders (isolated pocket)
  - A* fails to find path, but code added unreachable waypoint anyway
  - Sprite tried to reach it via straight line, crossing walls
  - Fix: when A* fails, `break` instead of `reconnectedPath.push(toWp)`
  - Sprite now stays at last valid position and reports `blocked: true`

- [x] ***BACKEND*-P1: Position Resolution from Movement Reports (Phase 10.8 Fix 4)** `reverie.py:1243-1301, 3574-3580`
  - Position priority: `scratch.last_actual_pos` → Supabase SOT → env JSON → default
  - Movement reports update `last_actual_pos` for next step continuity
  - Ensures path planning uses actual frontend position, not stale backend estimate
  - Console logs position source (P1/P2/P3/P4) for debugging

- [x] **P1: Reachability Validation (Phase 10.8 Fix 6)** `reverie.py:101-202, 1897-1925`
  - Added `is_tile_reachable()` + `find_nearest_reachable_in_zone()` helpers
  - Validates `planned_pos` is reachable before writing to Supabase
  - Reroutes to nearest reachable tile in zone if original target blocked
  - Prevents "isolated pocket" destinations (walkable but surrounded by walls)
