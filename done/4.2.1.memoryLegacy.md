## **ARCHITECTURE OPTIMIZATION** {#architecture-optimization}
Many of our prompts require a concise summary of the agent, shorthanded as [Agent's Summary Description] in prompts above. In our implementation, this summary comprises agents' identity information (e.g., name, age, personality), as well as a description of their main motivational drivers and statements that describes their current occupation and self-assessment. 
Since this information is frequently used in many prompts, we synthesize it at regular intervals and access that synthesis as a cache. To achieve this:
- we perform a retrieval on the query "[name]'s core characteristics." 
- We then summarize the descriptors in the retrieved records by prompting the language model. 
For example:
How would one describe Eddy Lin's core characteristics given the following statements?- Eddy is a student at the Oak Hill College studying music theory and composition- Eddy is working on a new music composition [...]
This result: Eddy Lin is a student at Oak Hill College studying music theory and composition. He loves to explore different musical styles and is always looking for ways to expand his knowledge."
We follow the same process in parallel on the queries "[name]'s current daily occupation" and "[name's] feeling about his recent progress in life". The agent's name, age, and traits are concatenated with these three summaries as the cached summary.

Many other optimizations are possible. 
Currently, because plans are likely to change from the agent's initial version, we only generate the high-level plan in advance and then recursively decompose the near future into the moment-to-moment action plan just in time. 
Another optimization might be to batch dialogue generation as a joint prompt rather than iterating back and forth between the agents, and re-planning could be architected to only invalidate and update parts of plans that strictly require adjustment. 
Our current architecture runs sequentially in roughly real-time game time (where one second real time is one minute game time), but it may be parallelized such that each agent runs in parallel.



## **Stage 9: AI-generated location: Dynamic Spatial Memory Approach**


*Concept*
- spatial_memory file should be created upon completion of a current step - for the next step.
- This spatial_memory should contain full address based on the content and the action of the completed step, which should result in dynamic, unscripted, and serendipitous simulation 
-- correspondingly, baseline simulation should already have spatial_memory file generated for the first step.
- Current step's spatial memory should be injected into AI prompt when generating actions for the current step.
- In this schema, Validation should refer to the exact same spatial_memory file used for AI generation (in this setup, validation step is a somewhat redundant, but can minimize potential AI hallutinations)

This approach represents a significant improvement over the current static implementation. It aligns well with the goal of creating a more adaptive, emergent simulation where personas can "learn" and expand their world knowledge through actions, leading to unscripted behaviors.

### **1. Reasonableness of the Approach**
- **Dynamic Updates Promote Serendipity**: By updating spatial memory *after* a step based on its outcomes (e.g., if a persona visits or interacts with a new sector/arena/object, add it to their memory), the simulation becomes more organic. For example:
  - Isabella starts with only her apartment in memory.
  - After a step where she "goes to Hobbs Cafe" (perhaps from baseline or initial action), Hobbs Cafe gets added.
  - In the next step, AI prompts include Hobbs Cafe as accessible, reducing fallbacks.
- **Current Step's Memory for AI Prompts**: Injecting the *just-updated* memory into prompts ensures AI decisions are grounded in the persona's "experienced" world, minimizing hallucinations (e.g., suggesting impossible locations).
- **Validation Alignment**: Using the same dynamic memory for validation eliminates the current inconsistency (where prompts and validation sometimes use different filtered lists). Validation becomes a lightweight "sanity check" rather than a heavy corrective layer.
- **Baseline Handling**: Providing an initial spatial_memory.json for the first step fits perfectly—it's like a "starting knowledge base" that evolves from there.
- **Reduces Scripted Feel**: Current static memory leads to repetitive behaviors (e.g., always falling back to home). Your approach allows for exploration and surprises, like a persona discovering a new pub through social interactions.

Potential logical edge cases to consider:
- **What triggers additions:** - if persona ends step or rather - moving into a new sector, add this sector with observed arenas/objects into spacial memory to make characters aware of surroundings.
- **Forgetting/Pruning?** To prevent memory bloat, consider decay (e.g., remove rarely visited sectors over time) - *Suggest options that align with ALL existing Memory Systems (s_mem, scratch, a_mem)*
- **Shared vs. Personal Memory**: Decide if discoveries are persona-specific by default, but can propagate through conversations (only details specificly mentioned in the conversation).

```python
class DoubleEmotionScorer:
    """Arousal/importance classifier for Double memory retention weighting"""
    def __init__(self):
        self.supabase = get_supabase_client()

        self.use_lightweight_model = True  # Use gpt-4o-mini for emotion scoring
        
    def score_memory_batch(self, agent_id, batch_size=50):
        """Batch emotion scoring via Double RPCs to minimize token costs"""
        # Get unscored memories from Double schema
        unscored = self.supabase.rpc('dbl_get_unscored_memories', {
            'p_agent_id': agent_id,
            'p_hours': 24,
            'p_batch_size': batch_size
        })
        
        if not unscored.data:
            return {}
            
        emotion_scores = {}
        memories = unscored.data
        
        # Group memories for efficient batch processing
        memory_batches = [memories[i:i+batch_size] for i in range(0, len(memories), batch_size)]
        
        for batch in memory_batches:
            batch_prompt = f"""
            Analyze emotional intensity and importance for these memories (1-10 scale):
            
            {self.format_memory_batch(batch)}
            
            Return JSON: {{"scores": [{{"memory_id": "id", "arousal": 0.0-1.0, "importance": 0.0-1.0}}]}}
            """
            
            # Use lightweight model for cost control
            response = model_router.call_gpt_mini(batch_prompt, response_format="json_object")
            
            for score in response['scores']:
                emotion_scores[score['memory_id']] = {
                    'arousal': score['arousal'],
                    'importance': score['importance']
                }
        
        # Update emotion scores via Double RPC
        if emotion_scores:
            self.supabase.rpc('dbl_update_emotion_scores', {
                'p_emotion_scores': emotion_scores
            })
                
        return emotion_scores
        
    def calculate_retention_score(self, memory, emotion_data):
        """Calculate memory retention based on emotion weighting"""
        base_decay_rate = 0.1
        
        arousal_boost = emotion_data.get('arousal', 0.0) * 0.4
        importance_boost = emotion_data.get('importance', 0.0) * 0.3
        access_frequency_boost = memory.get('access_count', 0) * 0.1
        
        retention_multiplier = 1 + arousal_boost + importance_boost + access_frequency_boost
        effective_decay = base_decay_rate / retention_multiplier
        
        return min(effective_decay, 0.01)
```

```python
class DoubleAssistantBasedAgent:

        self.assistant = openai.beta.assistants.create(
            model="gpt-4o-mini",
            name=f"DoubleAgent_{agent_config['name']}",
            instructions=self.build_system_instructions(agent_config),
            tools=[
                {"type": "function", "function": self.get_double_memory_functions()},
                {"type": "function", "function": self.get_double_planning_functions()},
                {"type": "function", "function": self.get_double_interaction_functions()}
            ]
        )
        
    def get_double_memory_functions(self):
        """Memory functions backed by Double RPCs"""
        return {
            "name": "retrieve_memories",
            "description": "Retrieve memories from Double system",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string"},
                    "max_results": {"type": "integer", "default": 10}
                }
            }
        }
        
    def process_with_assistant(self, input_message, context):
        """Use Assistant with Double backend for cognitive processing"""
        thread = openai.beta.threads.create()
        
        # Get enhanced context from Double
        enhanced_context = self.supabase.rpc('dbl_get_enhanced_context', {
            'p_agent_id': self.agent_id,
            'p_base_context': context
        })
        
        # Add context and input to thread
        openai.beta.threads.messages.create(
            thread_id=thread.id,
            role="user",
            content=f"Context: {enhanced_context.data}\n\nInput: {input_message}"
        )
        
        # Run assistant
        run = openai.beta.threads.runs.create(
            thread_id=thread.id,
            assistant_id=self.assistant.id
        )
        
        # Handle function calls with Double backend
        return self.handle_assistant_run_with_double(thread.id, run.id)
        
    def handle_assistant_run_with_double(self, thread_id, run_id):
        """Handle assistant run with Double function calls"""
        while True:
            run = openai.beta.threads.runs.retrieve(thread_id=thread_id, run_id=run_id)
            
            if run.status == 'requires_action':
                tool_calls = run.required_action.submit_tool_outputs.tool_calls
                tool_outputs = []
                
                for tool_call in tool_calls:
                    function_name = tool_call.function.name
                    arguments = json.loads(tool_call.function.arguments)
                    
                    # Route function calls to Double RPCs
                    if function_name == "retrieve_memories":
                        result = self.supabase.rpc('dbl_retrieve_memories', {
                            'p_agent_id': self.agent_id,
                            **arguments
                        })
                        tool_outputs.append({
                            "tool_call_id": tool_call.id,
                            "output": json.dumps(result.data)
                        })
                
                # Submit tool outputs
                openai.beta.threads.runs.submit_tool_outputs(
                    thread_id=thread_id,
                    run_id=run_id,
                    tool_outputs=tool_outputs
                )
                
            elif run.status == 'completed':
                messages = openai.beta.threads.messages.list(thread_id=thread_id)
                return messages.data[0].content[0].text.value
                
            elif run.status in ['failed', 'cancelled', 'expired']:
                raise Exception(f"Assistant run {run.status}: {run.last_error}")
                
            time.sleep(1)
```
