## **Memory Optimization Implementation Plan**


  *After Double-Write Backend is stable*, phase in optimizations iteratively—start with pgvector for vector compression and deduplication, add routine templates for filtering duplicates, incorporate multi-stage compression and emotion-weighted retention via Edge Functions, and monitor with dashboards for 50%+ reductions in memory volume and costs, ensuring rollback options if quality drops below legacy benchmarks.


This document synthesizes findings from analyses in reference documents:
  *4.2.1.memoryLegacy.md* provides foundational code-level implementations for dynamic memory in simulations (dynamic spatial memory and double-record systems).
  *4.2.2.Optimization.md* focuses on efficiency optimizations like prompt caching and vector compression (architecture efficiencies for prompts, memory, and planning).
  *4.2.3.bestpractices.md* advances to modern AI patterns including hierarchical search and self-reflection, with a production-ready addendum using OpenAI Assistants and Supabase (advanced AI memory techniques with layered stacks and emotion-weighted retention).

*Check existing Supabase Infra:* 
  Set according to "PART A: Supabase Infrastructure ✅" section at @docs\3.frontend-backend_split.md.

### Phase 0: Preparation (1-2 days)
- **Core Concepts**: Establish layered memory (semantic vs episodic from 4.2.3.bestpractices.md) with dynamic updates (from 4.2.1.memoryLegacy.md). Use Supabase pgvector for storage (4.2.2.Optimization.md).
- **Implementation**:
  - Create dbl_ prefixed tables for isolation (4.2.1.memoryLegacy.md §Stage 9, 4.2.3.bestpractices.md §Addendum 1).
  - Implement routine templates and deduplication (4.2.3.bestpractices.md Addendum §2), including YAML-based daily routines to filter duplicates.
  - Set up initial dynamic spatial memory updates post-action for serendipity (4.2.1.memoryLegacy.md §Stage 9: AI-generated location).
- **Migration**: Backup existing JSON memories; set up dual-write to Double (4.2.1.memoryLegacy.md §Stage 9: Double-record memory system).
- **Monitoring**: Baseline token usage and query performance (4.2.3.bestpractices.md §Addendum 1).

### Phase 1: Core Efficiency (Week 1)
- **Core Concepts**: Reduce prompt verbosity, cache summaries (4.2.2.Optimization.md); implement multi-stage compression (4.2.3.bestpractices.md Addendum §3).
- **Implementation**:
  - Prompt caching via Double RPCs (4.2.2.Optimization.md §Reducing Prompt Verbosity, equivalent in 4.2.1.memoryLegacy.md §Stage 9: Prompt & Cognitive Optimization).
  - Vector compression and deduplication in pgvector (4.2.2.Optimization.md §Efficient Memory Management).
  - Function calling for on-demand memory (4.2.2.Optimization.md §Leveraging Modern LLM Features).
- **Migration**: Migrate 20% of agents to Double; verify consistency (4.2.1.memoryLegacy.md cross-check).
- **Monitoring**: Track dbl_api_error_rate <2% (4.2.3.bestpractices.md §Addendum 1).

### Phase 2: Advanced Features (Week 2)
- **Core Concepts**: Emotion-weighted retention (4.2.3.bestpractices.md Addendum §4); hierarchical search (4.2.3.bestpractices.md §Efficient Memory Retrieval).
- **Implementation**:
  - Batch emotion scoring with gpt-4o-mini (4.2.3.bestpractices.md §Addendum 4, integrated with 4.2.1.memoryLegacy.md §Stage 10: Advanced Memory Features).
  - Self-reflection buffer in Double (4.2.3.bestpractices.md §Leveraging Memory for Planning).
  - Unified state management (4.2.2.Optimization.md §Consolidating Agent State).
- **Migration**: Full dual-write; phased cutover per agent (4.2.3.bestpractices.md Addendum §7).
- **Monitoring**: Memory volume reduction >50% after 30 days (4.2.3.bestpractices.md §Addendum 1).

### Phase 3: Production Scaling (Week 3+)
- **Core Concepts**: OpenAI Assistants integration (4.2.3.bestpractices.md Addendum); model routing (4.2.2.Optimization.md §Leveraging Modern LLM Features).
- **Implementation**:
  - One Assistant per agent with Double-backed functions (4.2.3.bestpractices.md §Addendum 1).
  - Cost guardrails and auto-rollback (4.2.3.bestpractices.md §Privacy, Safety, and Cost Controls).
  - Incorporate comprehensive monitoring and quality assurance (4.2.1.memoryLegacy.md §Stage 11: Production Optimization).
- **Migration**: Verify no Truman impact; enable emergency controls (4.2.3.bestpractices.md §Addendum 1).
- **Monitoring**: Comprehensive dashboard with alerts (4.2.3.bestpractices.md §Privacy, Safety, and Cost Controls); quality scores > baseline.

**Cost Controls**: Limit to $0.01/agent/sim day; use lightweight models for simple tasks (all analyses).
**Risks & Mitigations**: Schema isolation checks (zero violations); automated rollbacks if quality drops 15% (4.2.3.bestpractices.md §Addendum 1).
**Category Flexibility**: Predefined hierarchical categories (personal_relationships, work_activities, etc.) may not cover all domains. Consider auto-generating categories per agent from actual memory distribution, or add fallback to flat search when category confidence is low.
