## **'Double-docs' Setup (Symlink-Based)**

### *HOW-TO-USE*

1. **Editing Docs**:
   - Always edit files directly in the dedicated repo: `cd D:\Coding\double-docs`.
   - After changes: `git add . ; git commit -m "Your message" ; git push` (if remote exists).
   - Updates auto-propagate to frontend/backend via symlinks—no action needed in projects.

2. **In Projects (double-front, generative-agents)**:
   - Access docs via local `docs/` folder (symlink to double-docs).
   - View/edit as usual in IDE; changes save to source repo.
   - **Do NOT** commit or push docs from here—`docs/` is ignored in `.gitignore`.
   - For new clones/teammates: Run `setup.ps1` in project root (as Admin) to create symlink.

3. **Verification**:
   - In projects: `dir docs` (lists double-docs contents).
   - In double-docs: `git status` (track changes); `git log` (history).
   - Refresh IDE after setup to index symlinked files.

- **Frequency**: Commit in double-docs after every session or major update.
- **Tips**: If symlink breaks (e.g., path change), recreate with `New-Item -ItemType SymbolicLink -Path docs -Target "D:\Coding\double-docs"` (PowerShell as Admin). For cross-OS: Use `ln -s` on Unix.
