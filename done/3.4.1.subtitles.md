## **Implementation**

### How Subtitles Work

Subtitles provide real-time textual descriptions of key events in the simulation, enhancing user understanding, especially in complex or fast-paced scenarios. They are displayed at the bottom of the game canvas, fading in and out to avoid cluttering the view.

#### Key Features:
- **Event-Driven**: Subtitles are generated from filtered recent events that are visible within the camera bounds.
- **Synchronization**: Updates sync with agent moves and high-impact events.
- **Auto-Follow Integration**: When auto-follow is enabled, subtitles display the event description directly (e.g., "Maria and Klaus are chatting...").
- **Modes**: Automatically enabled in LIVE mode; optional in playback.
- **Accessibility**: Uses ARIA attributes where possible.
- **Primary vs Secondary**: Primary subtitles show high-impact scene events; secondary subtitles provide context for focused sprites when no primary events are active.

### Backend Architecture

The backend (`reverie.py`) has been updated to enrich the `movement.json` payload, exposing latent state data to enable deterministic subtitle generation on the frontend without additional LLM calls. These enrichments are written to `movement/{step}.json` files, which are then processed by `file_watcher.py` to update Supabase tables (e.g., `persona_positions`, `sceneEvents`). The new fields are propagated to Supabase via updates to `update_persona_coords` and related functions.

#### Payload Enrichment
The following fields are now included in the per-persona movement data in `movement.json` and synced to Supabase:

- **`chatting_with`**: 
  - *Source*: `persona.scratch.chatting_with`
  - *Format*: String (persona name) or null. For mutual chats, both agents point to each other (e.g., Maria: "Klaus", Klaus: "Maria").
  - *Purpose*: Enables frontend grouping. Detect mutual chats by checking if A.chatting_with === B.name && B.chatting_with === A.name.
  - *Supabase Propagation*: Stored in `persona_positions.chatting_with` (string, nullable). For `sceneEvents`, if mutual, backend pre-assembles "A and B are chatting" in `description`.

- **`address_label`**: 
  - *Source*: `maze.get_authoritative_address(next_tile)`
  - *Format*: String (e.g., "the Ville:Dorm:Kitchen"). Always authoritative; null only for invalid tiles (edge case <1% of steps).
  - *Purpose*: Provides readable location directly.
  - *Supabase Propagation*: Stored in `persona_positions.address_label`. Used in `sceneEvents.description` assembly (e.g., "in the Dorm Kitchen").

- **`intent`**: 
  - *Source*: Derived from `act_description` or `daily_req`.
  - *Format*: String (e.g., "research thesis").
  - *Logic*: If `act_description` contains "walking"/"going", fallback to `daily_req[-1]` (high-level goal). Otherwise, use `act_description`.
  - *Purpose*: Adds "why" context (e.g., "Heading to library to research thesis").
  - *Supabase Propagation*: Stored in `persona_positions.intent`. Appended to `sceneEvents.description` for transitional actions.

### Frontend Implementation

Subtitles are implemented using Phaser.js in the game scenes (`scenes/MainScene.ts` and related). The frontend consumes the enriched backend payload to assemble cohesive strings. Visual rendering has been moved to React UI via the `onSubtitleUpdate` callback; Phaser handles logic only.

#### Core Components:
- **subtitlesContainer**: A `Phaser.GameObjects.Container` positioned at the bottom-center of the canvas, with a semi-transparent black background rectangle for readability.
- **subtitlesText**: A single `Phaser.GameObjects.Text` element for displaying the subtitle content, styled as bold dark grey (`#333333`, 24px).
- **updateSubtitles(newText: string)**: Updates the subtitle text, applies fade-in tween (500ms alpha from 0 to 1), and ensures container visibility.
- **fadeOutSubtitles()**: Applies fade-out tween (500ms alpha to 0) after timer expiration, hiding the container.
- **subtitlesVisibleUntil**: Timestamp tracking end of 1 simulation step visibility (1000ms from update).
- **currentSubtitles**: Tracks current text to avoid unnecessary re-renders.

#### Initialization (in `MainScene.create()`):
- Create the `subtitlesContainer` and position it (e.g., x: camera.width / 2, y: camera.height - 50).
- Add a semi-transparent black rectangle (400x80, alpha 0.7) as background.
- Initialize `subtitlesText` as a child text object with bold dark grey styling, initial alpha 0.
- Set scrollFactor 0 to fix to camera.

#### Update Logic (in `MainScene.update()`):
- If `showSubtitles` flag is true:
  - Filter recent events (last 5 steps, visible within camera bounds via centroid check).
  - **Subtitle Assembly**: Use enriched fields (`chatting_with`, `intent`, `address_label`) to construct strings (e.g., "Agent A greets Agent B | Tension rises in the market").
  - Detect step change (`currentStep !== prevCurrentStep`) or text change; if so, call `updateSubtitles(finalText)` and set `subtitlesVisibleUntil = now + 1000`.
  - If timer expired (`now > subtitlesVisibleUntil`) and text visible, call `fadeOutSubtitles()`.
- Handle manual input to pause auto-features.
- In live mode, auto-enable and sync with real-time updates (throttled to avoid lag); each subtitle visible for 1 step unless replaced.

#### Primary Subtitle Assembly
The frontend assembles primary subtitles deterministically from raw enriched fields (no LLM). Pseudocode:

```typescript
function assembleSubtitle(event) {
  let text = "";
  
  // 1. Check for chat grouping
  if (event.chatting_with && isMutualChat(event.personaId, event.chatting_with)) {
    // Use alphabetical sorting for consistent naming
    const names = [event.name, event.chatting_with].sort();
    
    // Location formatting: "the Ville:Dorm:Kitchen" -> "Dorm Kitchen"
    const formattedLocation = event.address_label 
      ? event.address_label.split(':').slice(-2).join(' ') 
      : 'the Ville';
      
    // Simplified names (first name only)
    text = `${names[0].split(' ')[0]} and ${names[1].split(' ')[0]} are chatting in ${formattedLocation}`;
  } 
  // 2. Check for transitional intent
  else if (event.description.includes("walking") || event.description.includes("going")) {
    text = `${event.name.split(' ')[0]} heads to ${event.address_label} to ${event.intent}`;
  } 
  // 3. Default: Use description + location
  else {
    text = `${event.description} in ${event.address_label}`;
  }
  
  // 4. Append auto-follow if active (Simplified)
  if (autoFollowActive) text = text; // "Focusing on" prefix removed
  
  return text;
}
```

#### Secondary Subtitle Assembly
Secondary subtitles activate when no primary (high-impact) events are visible in the camera view. They describe the focused sprite (closest to camera center) using stored persona data. The logic is in `generateSecondarySubtitles()`:

- **Selection**: Filter visible sprites, sort by distance to camera center, select the closest.
- **Data Retrieval**: Pull `action`, `chattingWith`, `addressLabel`, `intent` from sprite data.
- **Formatting Rules**:
  1. **Chatting**: "[Name] is chatting with [Partner] at [Location]" (e.g., "Maria is chatting with Klaus at cafe - customer seating").
  2. **Transit**: "[Name] heads to [Location] to [Intent]" (e.g., "Maria heads to Dorm - Hallway to research thesis").
  3. **Generic Action**: "[Name] [Short Action] at [Location]" (e.g., "Isabella finishing her morning routine at cafe - kitchen").
     - **Short Action**: Truncate at first comma (e.g., "finishing her morning routine, which includes..." → "finishing her morning routine").
     - **Location**: Last two colon-separated parts with " - " (e.g., "the Ville:Hobbs Cafe:cafe:customer seating" → "cafe - customer seating").
- **Priority**: Secondary only shows if primary is empty; both use the same `updateSubtitles()` callback to React.

#### Fallbacks for Low-Event Periods
For steps with no high-impact visible events (poignancy < 5), the backend includes a `routine_summary` in `movement.json` meta (e.g., "Routine activities continue in the Ville"). Frontend displays: "Quiet moment in [address_label]". If missing, fallback to "Observing daily life."

#### Realtime Integration
- **Channel Schema**: Subscribes to Supabase Realtime `simulation_updates` for `movement.json` changes. Payload includes full enriched persona data (e.g., `insert` on `persona_positions` with `chatting_with`, `intent`, etc.).
- **Offline-First**: Enrichments cached in Expo AsyncStorage (key: `movement_step_{step}`). Syncs on reconnect.
- **Edge Cases/Null Handling**:
  - `chatting_with` null: Treat as solo action.
  - `address_label` null: Fallback to "the Ville".
  - `intent` null: Use raw `description`.
- **Performance**: Enrichments add ~5% to payload size (<1KB/persona). Edge Functions bundle <10MB, execution <500ms/step.

#### Integration with Story Stream:
- Subtitles sync with timeline markers, auto-follow camera, and conflict filters.
- In playback mode, hover previews show subtitle highlights.
- For low-event periods, subtitles fallback to overview summaries or routine descriptions.

#### Mobile and Responsiveness:
- On smaller screens, stack multi-line subtitles or reduce font size.
- Test for touch interactions and visibility during camera pans.

#### Performance Considerations:
- Limit subtitle updates to every 1-2 seconds in live mode.
- Reuse text objects to minimize Phaser object creation.
- Ensure compatibility with Phaser's accessibility plugins for screen readers.

This implementation draws from YouTube-style captioning, adapted for interactive simulations, ensuring seamless integration with the overall Story Stream engage features.
