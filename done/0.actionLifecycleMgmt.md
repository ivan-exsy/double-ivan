## **What is Action Lifecycle Management?**

Action Lifecycle Management is the core system that governs how AI agents transition through their daily activities over time. It manages the complete lifecycle of agent actions from planning to execution to completion, ensuring agents behave realistically by following schedules, completing tasks, and progressing through their day.

**Key Responsibilities:**
- **Schedule Management**: Creating and maintaining daily activity schedules
- **Action Transitions**: Determining when to start new actions based on time and completion
- **Emergent Behavior**: Handling social interactions that interrupt planned activities
- **State Consistency**: Ensuring agent state remains coherent across action changes

---

## **Core System Architecture**

### **1. Daily Schedule Creation (`_long_term_planning`)**
```
Daily Planning (once per day) → Hourly Schedule → Minute-level Decomposition
```

- **Trigger**: New day detection or "First day" simulation start
- **Process**: AI generates daily goals and creates `f_daily_schedule` with `[task, duration]` pairs
- **Output**: Complete 24-hour schedule broken into minute-resolution activities

### **2. Action Selection (`_determine_action`)**
```
Schedule Index Calculation → Current Action Extraction → Address Generation → Action Creation
```

- **Trigger**: `persona.scratch.act_check_finished()` returns `True`
- **Process**: 
  - Calculate current schedule index using `get_f_daily_schedule_index()`
  - Extract next action from `f_daily_schedule[curr_index]`
  - Generate location address through AI planning
  - Create new action via `add_new_action()`

### **3. Action Execution (`execute`)**
```
Address Resolution → Pathfinding → Movement Coordination → State Update
```

- **Process**: Convert action address to tile coordinates and plan movement path
- **Output**: Next tile position, emoji, and human-readable description

### **4. Action Completion Check (`act_check_finished`)**
```
Time Comparison: curr_time >= (act_start_time + act_duration)
```

- **Trigger**: Called every simulation step in `plan()` function
- **Logic**: Uses `>=` comparison to handle timing precision issues
- **Critical Fix**: Previously used `==` which caused actions to never complete

## **Implementation Details**

### **Schedule Index System** 
**Location**: `persona/memory_structures/scratch.py:322`

```python
def get_f_daily_schedule_index(self, advance=0):
    today_min_elapsed = self.curr_time.hour * 60 + self.curr_time.minute + advance
    
    curr_index = 0
    elapsed = 0
    for task, duration in self.f_daily_schedule:
        elapsed += duration
        if elapsed > today_min_elapsed:
            return curr_index
        curr_index += 1
    return curr_index
```

**Purpose**: Calculates which action in the daily schedule should be active based on current time.

### **Action Completion Logic**
**Location**: `persona/memory_structures/scratch.py:559`

```python
def act_check_finished(self):
    if not self.act_address: 
        return True
        
    if self.chatting_with: 
        end_time = self.chatting_end_time
    else: 
        x = self.act_start_time
        if x.second != 0: 
            x = x.replace(second=0)
            x = (x + timedelta(minutes=1))
        end_time = (x + timedelta(minutes=self.act_duration))

    # CRITICAL: >= comparison prevents timing precision issues
    if self.curr_time >= end_time:
        return True
    return False
```

**Purpose**: Determines when current action should end and trigger new action planning.

### **Main Cognitive Loop**
**Location**: `persona/persona.py:206` and `persona/cognitive_modules/plan.py:1472`

```python
def move(self, maze, personas, curr_tile, curr_time):
    # Update time and check for new day
    self.scratch.curr_time = curr_time
    
    # Cognitive sequence
    perceived = self.perceive(maze)
    retrieved = self.retrieve(perceived)  
    plan = self.plan(maze, personas, new_day, retrieved)  # ← Action lifecycle managed here
    self.reflect()
    
    return self.execute(maze, personas, plan)

def plan(persona, maze, personas, new_day, retrieved):
    # PART 1: Daily planning if new day
    if new_day: 
        _long_term_planning(persona, new_day)

    # PART 2: Check if current action expired → create new action
    if persona.scratch.act_check_finished(): 
        _determine_action(persona, maze)  # ← New action created here
        
    # PART 3: Handle social interactions (can interrupt current action)
    if retrieved.keys():
        focused_event = _choose_retrieved(persona, retrieved)
        if focused_event:
            _chat_react(maze, persona, focused_event, "chat", personas)
```

## **Common Issues & Debugging**

### **Issue 1: Actions Never Complete**
**Symptoms**: Characters remain static, same action from step 0 to step N
**Root Cause**: `act_check_finished()` using `==` instead of `>=` comparison
**Fix**: Ensure progression fixes are applied

```python
# BROKEN (timing precision issues)
if self.curr_time == end_time:
    return True

# FIXED (handles timing variations)
if self.curr_time >= end_time:
    return True
```

### **Issue 2: Schedule Index Not Advancing**
**Symptoms**: `get_f_daily_schedule_index()` returns same value
**Debug Steps**:
```python
# Check time progression
print(f"Current time: {persona.scratch.curr_time}")
print(f"Minutes elapsed: {persona.scratch.curr_time.hour * 60 + persona.scratch.curr_time.minute}")

# Check schedule structure
print(f"Daily schedule: {persona.scratch.f_daily_schedule}")

# Check index calculation
print(f"Current index: {persona.scratch.get_f_daily_schedule_index()}")
```

### **Issue 3: Social Interactions Not Triggering**
**Debug Steps**:
```python
# Check perception system
perceived = persona.perceive(maze)
print(f"Perceived events: {len(perceived)}")

# Check retrieval system
retrieved = persona.retrieve(perceived)
print(f"Retrieved contexts: {retrieved.keys()}")

# Check social reaction conditions
if retrieved.keys():
    focused_event = _choose_retrieved(persona, retrieved)
    print(f"Focused event: {focused_event}")
```

## **Key Takeaways for Developers**

1. **Action Lifecycle is Time-Driven**: Actions progress based on `curr_time` vs `act_start_time + act_duration`
2. **Schedule Index is Critical**: `get_f_daily_schedule_index()` must advance correctly for new actions
3. **Social Interactions are Emergent**: They can dynamically modify schedules and interrupt planned actions
4. **Timing Precision Matters**: Use `>=` comparisons, not `==`, for time-based checks
5. **Debug with Logs**: Enable progression tracking to monitor action transitions
6. **Test Edge Cases**: Late arrivals, interrupted actions, and schedule modifications

This system creates believable AI agents that follow plans but can adapt to social opportunities, just like real people!
