# Spatial Grounding Status Update

Date: 2026-03-27

## Executive Summary

We made substantial progress on the spatial grounding system.

The core issue at the start was that the system could decide an action in one
place, then effectively reinterpret location again later through a weaker,
prose-based path. That created mismatches such as clearly desk-based or
library-bound actions ending in the wrong room or object.

That situation is materially better now.

The system now has a stronger contract-first action/address flow, better
traceability when it degrades or falls back, and much stronger behavior on the
main transition path we care about.

This is not yet a final 10/10 state, but it is clearly in a better place than
when this work started.

## What Was Completed

### 1. Canonical Current-Action Contract

I introduced and integrated a canonical current-action contract so the system
has one primary executable representation of:

- what the persona is doing
- how long it should last
- what kind of subactivity it is
- what anchor it is associated with
- what resolved address it should execute at

This reduced the old multi-source-of-truth behavior across planner, runtime,
scratch state, and API normalization.

### 2. Planner-to-Contract Hardening

I hardened the planner bridge so contract downgrade and contract build failures
are no longer silent.

Instead of broad fail-open behavior, the system now distinguishes between:

- explicit validation downgrade
- unexpected planner contract errors

and makes both visible through counters, reason buckets, and runtime tags.

### 3. Runtime / API Alignment

I cleaned up runtime projection so downstream payloads prefer the canonical
contract and explicit resolved address instead of stale mirrors.

This materially improves consistency between planner state, runtime state, and
what reviewer-facing surfaces see.

### 4. Transition Grounding Hardening

I added narrow but system-level hardening for transition rows.

This included:

- keeping generic home-room anchors inside the persona's own room instead of
  drifting to unrelated common-room objects
- preserving the final destination-bearing travel phase when decomposition rows
  exceed the current subtask cap
- improving context-ordered grounding so local prep and destination travel are
  not confused as easily

### 5. Fallback Observability

One important improvement is that critical fallbacks are now much louder.

For contextual decomposition fallback, the system now records:

- fallback reason
- fallback kind
- transition fallback count
- runtime tags for traceability

And when a transition task falls back, it no longer collapses into a low-signal
generic loop. It now synthesizes a deterministic:

- prepare
- travel
- arrive

fallback shape when destination grounding is available.

### 6. Replay / Reporting / Monitoring Improvements

I also improved the reporting layer so postmortem review depends less on
console logs and more on exported artifacts.

This included improvements to:

- replay summary artifacts
- mismatch diagnostics
- monitoring traceability
- analyzer localization hints

That means the system is not only behaving better; it is also easier to debug
when something goes wrong.

## Current Result

### What Is Clearly Better

- The main contract-first path is much stronger than before.
- The old action/location mismatch problem has been materially reduced.
- Transition rows are handled better than before.
- The planner no longer hides important downgrade/error behavior.
- Fallback behavior is easier to see and classify.
- The reporting/debug loop is significantly better than at the start.

### What Is Still Not Fully Closed

- Raw coarse hourly transition rows are still weak inputs on their own.
- Some upstream hourly planning text is still too compound or transition-heavy.
- Some non-sleep local substeps still occasionally hit bed-like contract
  downgrade rules and fall back to compatibility behavior.
- I have not yet validated the full system with a fresh live sim backed by the
  normal persistence path.

## Known Problems Still Open

The main remaining weakness is not the core contract path anymore.

The remaining red signal is concentrated in this older family:

- direct coarse hourly row -> location interpretation

That is important because it means the system is stronger on the real
contract-aware path than on the older coarse-prose diagnostic path.

In practical terms:

- the main executable path is healthier
- the remaining weakness is now better isolated
- the system is no longer failing in the same broad, ambiguous way it was at
  the beginning

## What I Recommend To Reach 10/10

### 1. Run One Real End-to-End Sim

The next major milestone should be one controlled fresh sim run through the
normal persistence path, using the already-hardened backend.

That is the cleanest way to confirm that the current DB-free improvements hold
in the full runtime.

### 2. Keep Tightening Transition Representation

The remaining weakness is still most visible in coarse transition text.

I recommend one more narrow follow-up focused on:

- transition rows
- travel-phase preservation
- local-vs-destination disambiguation

without reopening the architecture.

### 3. Keep Fallbacks Loud

The system still contains legacy fallback paths, so they must remain explicit
and attributable.

The right direction is:

- fewer silent degradations
- more explicit reason codes
- better exported traceability in report artifacts

### 4. Treat the Contract-Aware Path as the Main Health Metric

The most important lesson from this work is that the main correctness metric
should be:

- contextual decomposition
- executable contract
- resolved address

not raw coarse hourly prose interpreted in isolation.

## Bottom Line

Compared with where this work started, the system is in a substantially better
state.

The spatial grounding architecture is stronger, the transition path is more
stable, fallback behavior is more visible, and the remaining problems are much
better isolated.

This is not yet a final “done” state, but it is a meaningful step forward and
it gives us a much cleaner base for the final push to a 10/10 system.
