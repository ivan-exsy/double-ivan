## Root Cause (corrected)

The original BE RCA diagnosed this as "FE has no proximity emission code." **This was incorrect.** A complete proximity detection and emission pipeline existed in the FE (`InteractionManager.ts`) but observations never reached the BE due to a **field name mismatch** between FE output and BE ingestion, plus a missing step-number wiring.

### What the FE was doing

The FE had a fully implemented pipeline:
- `checkProximity()` — pairwise segment-based distance checks every frame, called from `MainScene.update()`
- `updateStepProximityState()` — step-based batching of proximity events with duration tracking
- `flushStepObservations()` — emits observations into `window.__headlessObservations` at step end via `onStepComplete` callback

### Why it didn't work: field name mismatch

The FE emitted observations with field names that the BE could not parse:

| Field | FE emitted | BE expected (`reverie.py:7193-7203`) |
|---|---|---|
| Agent position | `location: [x, y]` | `position: [x, y]` |
| Distance | `details.minDistance` | `details.distance` (or `obs.distance`) |
| Other agent position | not emitted | `details.other_position: [x, y]` |

The BE's `_extract_observation_distance()` (`reverie.py:891`) searches for `distance`, `diistance`, `disstance` — but never `minDistance`. With no distance found, it falls through to the position-based fallback, but `obs.get('position')` also returned `None` (FE used `location`). Result: **`distance` defaulted to 999** for every observation.

### Additional issue: `setCurrentStep()` never called

`InteractionManager.setCurrentStep()` was defined but never invoked. `this.currentStep` stayed at `0` for all observations, and the step-change-based flush path never triggered. Flushing only worked via the `onStepComplete` callback, but all observations reported `step: 0`.

### What was correct in the original RCA

- `pending.json` containing only `movement_report` entries — confirmed (movement reports go to `window.__headlessReports`, a separate array)
- The full BE pipeline being implemented and ready — confirmed (all functions, guards, cooldowns verified at stated line numbers)
- Env flag analysis (`OBSERVATION_PRIMARY`, `ENABLE_HEADLESS_VALIDATION`) — correct

### What was incorrect

- "FE has no code path that computes pairwise distances and emits proximity observations" — **wrong**, `InteractionManager.ts` had a complete implementation
- "`window.__headlessObservations` only ever contains movement reports" — **wrong**, movement reports go to `window.__headlessReports`; `__headlessObservations` is exclusively for proximity data

## Env Flags (relevant)

| Flag | Value | Effect |
|---|---|---|
| `OBSERVATION_PRIMARY` | `true` (default) | BE expects FE to drive chat triggers via proximity observations |
| `ENABLE_HEADLESS_VALIDATION` | `false` (default) | Plan-path `lets_talk()` falls through to legacy LLM instead of returning `False` |

Because `ENABLE_HEADLESS_VALIDATION=false`, the plan-path LLM fallback is still active — that's why 2 chats exist at all. If this flag were `true`, there would be **zero chats** since the observation path is the only path and it was broken.

## Fixes Applied (2026-03-23)

All changes on the FE side — no BE modifications required. The FE is the producer; it conforms to the BE's existing ingestion contract.

### 1. Field name alignment (`InteractionManager.ts: flushStepObservations()`)

Observation output now matches the BE contract:
- `location` -> `position` (top-level agent position in tile coords)
- `details.minDistance` -> `details.distance`
- Added `details.other_position` (second agent's tile coords)

### 2. Per-agent position tracking (`InteractionManager.ts`)

- `StepProximityState` now tracks `lastOtherLocation` alongside `lastLocation`
- `checkProximity()` passes individual sprite positions (`pos1`, `pos2`) instead of the midpoint
- `updateStepProximityState()` stores both agent positions for accurate tile-coordinate emission

### 3. Step number wiring (`AnimationManager.ts` + `MainScene.ts`)

- Added `onStepStart(stepNumber)` callback to `AnimationManager`, fired early in `executeStepForHeadless()` after step number resolution
- `MainScene` wires `onStepStart` -> `interactionManager.setCurrentStep()` in both `initManagers()` and `setCallbacks()`
- Observations now carry the correct step number; step-change-based flush path is functional

### 4. Type contract update (`headless-types.ts`)

- `HeadlessObservation.location` -> `position`
- `details.minDistance` -> `details.distance`
- Added `details.other_position?: [number, number]`

### 5. Debug panel (`HeadlessObservationsPanel.tsx`)

- Updated to use new field names

### Files changed

| File | Change |
|---|---|
| `scenes/managers/InteractionManager.ts` | Field names, per-agent positions, state shape |
| `scenes/managers/AnimationManager.ts` | `onStepStart` callback + setter |
