## RCA-1 — Piano as cafe hangout leaf (S1)

### Viewer symptom
Someone is “walking to Hobbs / ordering coffee / paying,” but the **planned destination leaf is the piano**. Presence line often still says cafe/Ville, so the status bar may look fine while the body **paths toward the piano prop**. Feels fake: coffee at the piano.

### Evidence (`20260730-1`)
- Analyzer V2: **78** steps, non-piano acts with `:piano` in planned address / `zone_resolution_detail`.
- Vince ~40, Owen ~24; streaks while walking to / hanging at Hobbs (e.g. Vince 331–333).
- Spot pattern: `address_label` often **not** piano; planned leaf **is** piano (`zone_only`). Not Class P (wrong building).

### Mechanism
1. Somewhere earlier, Hobbs resolve seals `:piano` (social interaction candidate; piano has `affordance_required` + play/social tags).
2. Later rows **reuse contract / sticky** because sector still matches “Hobbs Cafe” — travel named-dest protect only checks **sector**, not leaf affordance.
3. Post-validate / remap often **no-ops on depth-4 addresses** (`count(":") >= 3` skips object re-pick), so “forbidden piano” is detected but not cleared.
4. `_pick_object_for_interaction` can still introduce piano for `social`; R6 skip lives mainly on `_pick_best_object_address`.

### Root (ranked)
| Rank | Hypothesis | Status |
|------|------------|--------|
| 1 | Contract/sticky short-circuit keeps sealed `:piano` across non-piano cafe acts | **Primary** — matches long streaks |
| 2 | Depth-4 remap cannot re-pick seating when leaf is affordance-forbidden | **Contributing** |
| 3 | Interaction-pick path ignores `affordance_required` | **Introduction path** |
| 4 | Analyzer counts planned leaf (by design) | Measurement OK; runtime still wrong |

### Recommended fix (MVP pass)
**Ship together (small):**
1. **Contract + sticky reuse:** if leaf has `affordance_required` and act text does not match required affordance → **reject reuse**, re-resolve / post-validate.
2. **Remap Tier-1:** if current leaf is affordance-forbidden, force in-arena `_pick_best_object_address` with piano unavailable (customer seating), **never** Tier-4 home-snap on named Hobbs travel.
3. **Parity:** add `affordance_required` skip to `_pick_object_for_interaction` (same as R6 default pick).

**Do not:** mass-retile Hobbs; keyword-ban “piano” in prompts alone.

### Prove bar

- Next score sim: V2 ≪ 78 (target near 0 for non-play acts); spot no multi-step `zone_detail=…:piano` on walk/order/pay.
