## **PRD: Simulation Viewer "Story Stream"**

### Overview
Enhance the simulation viewer (e.g., `app/simulations/[sim_code]/page.tsx` and `GameCanvas.tsx`) with a YouTube-inspired "Story Stream" interface to improve user comprehension and engagement. This integrates subtitles, auto-follow camera, timeline markers, and a conflict/drama filter into a cohesive system. Targets quick grasping of events in live or playback modes, using event streams from Supabase/WebSocket.

**Version**: 1.0  
**Priority**: High (MVP enhancement)  
**Stakeholders**: Users (viewers), Dev Team  
**Dependencies**: Existing event stream in `useSimulation.ts`, Phaser camera controls in `GameCanvas.tsx`.

### Goals
- Enable rapid understanding of simulation dynamics (e.g., drama, chats, routines).
- Create an immersive, video-like experience without overwhelming the UI.
- Support live (real-time) and playback modes.
- Minimize manual interaction while allowing overrides.

### Key Features & Requirements

#### 1. Subtitles (Event Narration)
   - **Description**: Semi-transparent overlay at canvas bottom (rendered in React UI via onSubtitleUpdate callback from Phaser logic) displaying humanized event descriptions assembled deterministically from enriched backend fields (e.g., "Maria and Klaus are chatting in Dorm Hallway"). Distinguishes primary subtitles (high-impact events, poignancy >5) from secondary (descriptions of focused sprite when no primary visible). Filters recent visible events (last 5 steps, centroid in camera bounds); joins into cohesive strings. Fades after 1 simulation step (1000ms visibility), with 500ms alpha tween in/out.
   - **Activation**: YouTube-style 'CC' toggle button in controls bar.
   - **Integration**: Pull from event stream in `useSimulation.ts`; sync with auto-follow (display event descriptions on camera moves).
   - **Requirements**:
     - Responsive: Stack vertically or reduce font on mobile.
     - Accessibility: ARIA labels/live regions, compatible with screen readers.
     - Data: Coalesce using enrichments like chatting_with (mutual chat detection), address_label (formatted location), intent (goal context); filter for on-screen relevance. Fallbacks for low-events (e.g., "Quiet moment in [location]").

#### 2. Auto-Follow Camera Mode
   - **Description**: Dynamically pans/zooms camera to high-impact events, ranked by scoring (drama >> chat >> routine; composite = arousal * novelty * impact from event metadata).
   - **Activation**: Enabled by default; disables on manual map movement (drag/zoom); auto-re-engages after 10s inactivity.
   - **Behavior**:
     - Focus on highest-ranked event centroid (e.g., midpoint of agents).
     - For concurrent top-ranked events: Alternate every 10s with smooth pan (Phaser lerp 0.1-0.3).
     - Sync subtitles with moves.
   - **Requirements**:
     - Cooldown: Min 5s between follows to avoid whiplash.
     - User Prefs: Toggle in controls; sensitivity settings (e.g., "Drama Only").
     - Fallback: Overview mode if no events.
     - Modes: Works in live (real-time follows) and playback (jumps to markers).

#### 3. Timeline Markers

   - **Description**: YouTube-style chapters on progress bar (scrub bar spans sim time, real-time or accelerated).
   - **Behavior**: Auto-populate with icons/tooltips (e.g., 💔 for drama); color-coded by type (red=drama, yellow=chat, gray=routine).
   - **Integration**: Generated from event beats; clickable for jumps.
   - **Requirements**:
     - Indicators: Small YouTube-style dots for high-impact events (default on).
     - Sync: Preview subtitles/highlights on hover; integrate with auto-follow for jumps.

#### 4. Conflict/Drama Filter
   - **Description**: Highlights drama via visual cues (e.g., sprite glows, trails); toggles dynamic playback.
   - **Default State**: Show small indicators on timeline for high-impact events.
   - **Activated Mode** (Toggle in left bottom corner, post-timeline):
     - High-Impact Events: Zoom to 1.0x on scene, play at 1x speed.
     - Routine/Mundane Events: Zoom out to full map, play at 5x speed.
   - **Deactivated Mode**: Use YouTube-style bell notifications or end-screen cards for pings (e.g., "Tension rising—tap to view"); limit to 3 active, stack in side panel.
   - **Requirements**:
     - Thresholds: Activate based on event scores (>2 for high-impact).
     - UI: Phaser overlays for highlights; smooth speed/zoom transitions.
     - Modes: Applies to playback; optional in live (auto-activate on drama).

### UI/UX Guidelines
- **Layout**: Timeline at bottom; controls bar above (CC button, auto-follow toggle, drama filter switch).
- **Visual Style**: Minimalist (Tailwind CSS); responsive for web/mobile.
- **Interactions**:
  - Manual overrides disable autos (e.g., scrub exits auto-follow).
  - LIVE Mode: Auto-enable subtitles/auto-follow; show 🔴 badge.
- **Accessibility**: Keyboard shortcuts (e.g., 'C' for CC); high-contrast modes.

### ✅ *Backend - Implementation Summary*

**Event Enrichment and Scoring**: Added `_calculate_event_scores` method in `reverie.py` during `_process_pending_observations`. Computes arousal (type-based map, e.g., conflict=0.9), novelty (1 - repeat frequency over 100-event history), impact (0.4 + 0.15*agents), and composite (product). Generates humanized descriptions (e.g., "Ava confronts Leo"). Flags high-impact (>0.5). Enriched data appended to `obs['details']`; history tracked via `deque(maxlen=100)`.

**WebSocket Enhancements**: In `websocket_manager.py`, added `ConnectionType.EVENT` and conditional broadcasting for "new_observations" (uses EVENT type). In `file_watcher.py`, synced enriched events into `enhanced_data['events']` array during `_broadcast_movement_update` for batched, real-time sync with movements. Removed separate broadcasts; throttled via `broadcast_delay=1s`. Reuses existing error handling (failed client cleanup) and queues.

**Dependencies & Storage**: No new tables; appends to existing `details` in Supabase upserts (`_update_database_coords`). Supports live (real-time timestamps) and playback (query historical steps).

**Phasing**:
- **MVP Complete**: Scoring, enrichment, and basic broadcasts ready for subtitles/markers.
- **v2 Ready**: Structure supports filtering (e.g., broadcast only high-impact); extend for auto-follow/drama.

**Risks Mitigated**: O(1) scoring; defaults (arousal=0.2 for unknown); limits to ~10 events/step.

### ✅ *Backend - Subtitles Enrichment*
**Payload Enrichment**: In `reverie.py`, added fields to per-persona movement data in `movement.json` and Supabase `persona_positions`: `chatting_with` (string or null for mutual chats), `address_label` (e.g., "the Ville:Dorm:Hallway"), `intent` (derived from act_description or daily_req). Backend pre-assembles some descriptions in `sceneEvents` (e.g., "A and B are chatting in [location]"); frontend handles deterministic assembly for others. Supports routine_summary in meta for low-event fallbacks.

**Supabase Propagation**: Fields upserted via `_update_database_coords`; Realtime channel `simulation_updates` broadcasts enriched data.

**Examples**:
Sample `movement.json` per persona:
```json
{
  "Maria": {
    "chatting_with": "Klaus",
    "address_label": "the Ville:Dorm:Hallway",
    "intent": "research thesis",
    "description": "chatting with Maria"
  }
}
```
Sample `sceneEvents` row:
```json
{
  "step": 456,
  "description": "Maria and Klaus are chatting in the Ville:Dorm:Hallway",
  "centroid": [58.5, 9]
}
```

**Performance**: Adds ~5% payload size; Edge Functions <500ms/step.

### **Frontend Implementation Plan**

This plan builds on lessons from the initial attempt: prioritize modularity to avoid bloating large files like GameCanvas.tsx, centralize types for TypeScript safety, extract logic to custom hooks and helper methods, implement incrementally with frequent builds/tests/commits, and use exact Phaser types to prevent cascading errors. We'll recreate necessary files (e.g., scenes/GameScene.ts for CustomScene interface, scenes/MainScene.ts for the scene class) as needed.

1. ✅ **Setup and Modularization Foundation**:
   - Create `scenes/GameScene.ts`: Define `interface CustomScene extends Phaser.Scene` with required Phaser properties (e.g., input: Phaser.Input.InputPlugin; time: Phaser.Time.Clock; tweens: Phaser.Tweens.TweenManager; children: Phaser.GameObjects.DisplayList;) and placeholders for custom props/methods (e.g., subtitlesContainer?: Phaser.GameObjects.Container; updateSubtitles?(newText: string): void;). Add types for Event, StepData, etc.
   - Create `scenes/MainScene.ts`: Export class MainScene extends Phaser.Scene implements CustomScene { ... } with class fields matching the interface (required ones without ?, optionals with ? and = undefined). Include minimal create()/update() stubs.
   - In `components/GameCanvas.tsx`: Import MainScene and update Phaser config to { scene: MainScene }. Change sceneRef to useRef<CustomScene | null>(null). Extract complex useEffects to custom hooks in `hooks/` (e.g., usePhaserSetup.ts for game creation, useAnimationSync.ts for step animations, useScenePropSync.ts for prop updates).
   - Commit: "Setup: Modularize Phaser scene with types and hooks".
