# Legacy Django Frontend Movement Implementation Analysis

This document analyzes the legacy Django frontend implementation to understand how sprite movements, animations, and stationary activities are handled to avoid "frozen" or unrealistic character behavior.

## *1. Obstacle Avoidance & Collision Detection*

### Backend Pathfinding System
The obstacle avoidance is primarily handled by the backend pathfinding system:

**Path Finding Algorithm (`reverie/backend_server/path_finder.py`)**:
- Uses a flood-fill pathfinding algorithm (`path_finder_v2`) that treats collision blocks as obstacles
- Collision detection uses `collision_maze.csv` where non-zero values represent walls/obstacles and `0` represents walkable tiles
- Coordinate system conversion: Input (x,y) → Internal (y,x) → Output (x,y)

**Movement Validation (`reverie/backend_server/persona/cognitive_modules/execute.py`)**:
```python
# WALL-WALKING PREVENTION: Ensure path doesn't go through walls
collision_free_path = []
for coord in path[1:]:  # Skip first element (current tile)
  if coord and len(coord) == 2:
    x, y = coord
    if 0 <= x < maze.maze_width and 0 <= y < maze.maze_height:
      collision_free_path.append(coord)
```

**Frontend Collision Layer (`templates/home/main_script.html`)**:
- Phaser.js collision layer: `collisionsLayer.setCollisionByProperty({ collide: true })`
- Uses Tiled map editor collision properties to define impassable areas
- Collision layer depth set to -1 (invisible but functional)

### Movement Authority
- **Backend Authority**: Backend calculates valid paths and sends target coordinates
- **Frontend Compliance**: Frontend instantly positions sprites at backend-validated targets
- **Position Reconciliation**: System snaps frontend positions to match backend authority at step completion

## *2. Active Movement Visualizations*

### Animation System Architecture
The frontend uses a phase-based animation system driven by backend computations:

**Phase-Based Animation System (`templates/home/main_script.html`)**:
```javascript
// PHASES: process (send positions), update (poll backend), execute (move to target)
// Movement is single-tile, instant (1 frame per step)
let phase = "update"; // Cycles: process → update → execute
let movement_speed = 32; // Matches tile size for instant move
let execute_count_max = 1; // 1 update cycle per tile
```

**Character Sprite Sheets**:
- Texture atlas (`atlas.png/json`) with pre-sliced frames for "Misa" character
- Animation sets: 4 frames per direction (walking left/right/front/back)
- Frame organization: Named frames like "misa-left-walk.000" to ".003"

**Walking Animation Implementation**:
```javascript
// Direction-based animations with 4fps frame rate
anims.create({
  key: "misa-left-walk",
  frames: anims.generateFrameNames("atlas", { prefix: "misa-left-walk.", start: 0, end: 3, zeroPad: 3 }),
  frameRate: 4,
  repeat: -1
});
```

### Movement Execution
**Instant Tile Positioning**:
- Single-tile moves only (backend computes one adjacent target per step)
- Direction determined by delta (x then y priority: left/right before up/down)
- Sprite position updated in one frame: `body.x/y += 32px` (tile width)
- No interpolation or easing—discrete snapping to prevent drift

## *3. Stationary Activity Visualizations*

### Idle Animation System
**Static Frame Selection**:
```javascript
// Stop walking animation, show idle frame based on last movement direction
curr_persona.anims.stop();
if (pre_anims_direction_dict[curr_persona_name] == "l") curr_persona.setTexture("atlas", "misa-left");
else if (pre_anims_direction_dict[curr_persona_name] == "r") curr_persona.setTexture("atlas", "misa-right");
else if (pre_anims_direction_dict[curr_persona_name] == "u") curr_persona.setTexture("atlas", "misa-back");
else curr_persona.setTexture("atlas", "misa-front"); // Default down
```

**Activity Phase System**:
- After instant move, sprite idles on static frame until next backend step
- Maintains last movement direction for contextual idle positioning
- No fixed activity duration—step-driven by backend polling cycle

### Visual Feedback Elements
**Speech Bubbles & Pronunciations**:
- Dynamic text display above characters: `pronunciatios[persona_name].setText(initials + ": " + pronunciatio_content)`
- Bubbles follow character positions during/after moves
- Updated per step with backend "pronunciatio" content

**Status Indicators**:
- Current action display: `document.getElementById("current_action__"+persona_name).innerHTML = description_content.split("@")[0]`
- Target location: `document.getElementById("target_address__"+persona_name).innerHTML = description_content.split("@")[1]`
- Chat content display for social interactions

## *4. Key Anti-Freeze Mechanisms*

### Continuous Animation Cycle
1. **Movement Phase**: Brief walking animation during the single-frame move (if direction changes)
2. **Idle Phase**: Static directional frame during stationary periods between steps
3. **Step-Driven Updates**: Backend polling ensures regular position refreshes
4. **Direction Memory**: `pre_anims_direction_dict` maintains context to avoid jarring idles

### Position Authority & Validation
- **Backend Authoritative**: All movement targets computed by backend pathfinding
- **Frontend Validation**: Optional `position_feedback.js` reports discrepancies (tolerance=3 tiles)
- **Drift Correction**: Automatic snapping to authoritative positions at execute end
- **Fallback Systems**: Idles on invalid moves; polling retries on backend delays

### Performance Optimizations
- **Polling Throttling**: `timer_max` controls update frequency to avoid overburdening backend
- **Selective Updates**: Only processes active personas in loops
- **Phaser Efficiency**: Arcade physics and atlas reuse minimize overhead

## *5. Technical Implementation Details*

### Coordinate Systems
- **Frontend**: (x, y) pixel coordinates with 32px tile size (`Math.ceil(pos / 32)` for tile conversion)
- **Backend**: (x, y) tile coordinates converted to/from (y, x) internally
- **Collision**: CSV grid using (row, col) indexing

### Error Handling
- **Path Validation**: Multi-stage in backend (bounds → collision → reachability)
- **Graceful Degradation**: Fallback to stay put if target invalid
- **Position Reconciliation**: Snapping corrects any minor frontend drift

### Animation Performance
- **Frame Rate**: 4fps for walking animations (brief, efficient for instant moves)
- **Step Timing**: Driven by backend computation cycle (e.g., ~10s/step); no fixed animation cycles
- **Memory Management**: Phaser global anims manager reuses across characters

This system creates discrete, turn-based character navigation that mirrors backend states exactly, prioritizing accuracy over smooth interpolation while using directional idles to maintain visual engagement during stationary periods.
