# **Fixes For Stationaty Sprite Behavior**

## *Movement Coordinate Architecture Fix (Post-Backend Clarification)*

### Summary of Backend Response
The hybrid model **is active**. Key clarifications:
- `movement` = **current position** (authoritative, where sprite IS after execution)
- `target_zone` = **destination intent** (where AI wants sprite to GO)
- `speed_multiplier` = 0.0 means **stay in place**; >0.0 means **move**
- Backend already consumes reports via `_handle_movement_report()` (lines 2876–2932)
- Stationary: `target_zone` is small (±3 tiles around current) or `null`, `speed_multiplier=0.0`

### Root Cause of `20251216-7` Bug
Frontend was **ignoring `speed_multiplier`** and treating any `target_zone` presence as "move immediately". When `speed_multiplier=0.0` (stay), frontend should idle—not pathfind.

### Backend Implementation Tasks (DETAILED)

#### 🚨 CRITICAL BUG: `speed_multiplier` Overwritten in JSON Serialization

**Location**: `reverie.py` lines 1466-1467

**Problem**: The `speed_multiplier` computed in `plan.py` (lines 1282-1291) is **overwritten** during JSON serialization:

```python
# plan.py correctly computes:
speed_multiplier = 0.0  # for "sleeping", "resting", "idle"
persona.scratch.speed_multiplier = speed_multiplier

# BUT reverie.py OVERWRITES it:
speed_multiplier = 1.5 if "run" in description.lower() else 1.0  # ❌ IGNORES scratch value
movement_data["speed_multiplier"] = speed_multiplier  # Always 1.0 or 1.5!
```

**Impact**: Stationary actions (sleep, idle, rest) that should have `speed_multiplier=0.0` are serialized as `1.0`, causing frontend to pathfind when it should idle.

**Fix Required** (`reverie.py` line 1466):
```python
# USE the computed value from scratch instead of re-computing:
speed_multiplier = getattr(persona.scratch, 'speed_multiplier', 1.0)
movement_data["speed_multiplier"] = speed_multiplier
```
