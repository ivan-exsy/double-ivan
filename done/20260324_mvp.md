## MVP Definition

A viewer watching simulation playback should see:
1. Sprites moving believably (no visible jitter/oscillation)
2. Actions happening at plausible locations
3. Varied activity throughout the run (no dead stretches)
4. Natural conversations that fit context

The bar is **"looks alive and coherent on first watch"**, not perfect realism.

### *Root Cause Analysis*
Two plan.py bugs caused symptoms: Bug 1 (oscillation) - `_infer_subactivity_mode()` sets "in_place" but `_compute_stationary_state()` needs `has_stationary_hint` from limited keywords, keeping `stationary_intent=False` in 3-step arrival transitions (ARRIVAL_TRANSITION_EXPIRY_STEPS=3), leading to zone-nudging waypoints and endless resets; keyword fixes were brittle vs LLM variation. Bug 2 (stalls) - P2_ACTION_REFRESH_MAX_STEPS=8 triggers but action_switch_noop doesn't update p2_last_action_switch_step, stalling timer and allowing 60-step extensions.

### *Fixes*
~8-line edits in plan.py, preserving gates and dropping keyword deps. Fix 1 (oscillation): Refine arrival bypass to sub_mode != "zone_patrol" (new-action ~3303, continuation ~3862) for immediate stationary if in-zone; remove has_stationary_hint in fallback (~665) to trust sub_mode. Covers in_place (sleep/desk), workstation_hop (sketch/draft), social_touch (chat); retains transitions for zone_patrol (Gosha lab). Fix 2 (stalls): Reset p2_last_action_switch_step and extensions=0 in noop (~4098) for 8-step cycles. No prompt/env changes. Eliminates oscillation except Gosha gap; skip cafe/Ivan for MVP. ## ✅ **Phase 3: Analyzer hardening**

The original issue was that the realism analyzer in `analyze_sim_realism.py` reported 0 issues on sim 20260323-4, despite clear regressions like 28-step oscillations, 40-step dead clusters, and location mismatches. Existing detections covered basics like teleports and chat payloads, but missed behavioral signals: zone adherence was disabled, and oscillation, plan stall, early-sim stationary clusters, and activity-location mismatches were unimplemented. This left regressions invisible without manual reporting, undermining automated validation for MVP.

Fixes added five constants (e.g., `OSCILLATION_WINDOW=6`, `PLAN_STALL_MAX_RUN=15`) and three new functions: `_check_oscillation` (sliding window for ≤2 unique positions in 6+ steps, with contiguous run merging to avoid duplicates), `_check_plan_stall` (run-length encoding for action labels >15 steps, excluding sleeping), and `_check_stationary_cluster` (<3 unique positions in first 50 steps, skipping sleeping-dominant personas). These were wired into `validate_all`, emitting warning-severity issues with step ranges and details. Zone adherence remains disabled due to LLM non-determinism, but the bundle format supports LLM-assisted checks for mismatches.

Test results on sim 20260323-4 showed progress: from 0 to 102 issues initially (89 oscillation over-fires), refined to 51 issues (38 oscillation episodes like 28-step [122,21]/[122,22] runs, 13 plan stalls). No false positives; stationary cluster didn't fire as early movement exceeded threshold. Analyzer now catches real regressions (e.g., Gosha's repeated 2-tile loops), enabling proactive fixes without manual audits. Activity-location mismatches (e.g., cafe actions at library) surface in exports for LLM review, closing the P2-1 gap.
