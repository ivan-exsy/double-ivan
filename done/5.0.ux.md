## **1. Sprite sticker representing actions & mood ✅**
Each agent is represented by a simple 2D sprite avatar with emojis above their heads in speech bubble style, showing current actions (generated via LLM translation of natural language outputs) and general status. Examples:
"Writing in journal" → 📖✏️
"Checking emails" → 💻📧
"Talking on phone" → 📱💬

### FRONTEND
- Frontend implementation is complete in GameCanvas.tsx using Phaser.js to render 2D sprites for avatars, with each sprite accompanied by a StatusSticker.tsx above the head displaying the 'pronunciatio' emoji (e.g., 📖✏️ for writing).
- Persona interface in lib/api.ts and transformations in hooks/useSimulation.ts ensure firstName and pronunciatio are properly preserved and defaulted to '😐' if missing.

### BACKEND

The backend implementation for generating emojis from agent actions employs a multi-layered approach to ensure reliable translation of natural language descriptions into 1-2 relevant emojis. The process begins in plan.py with action determination, passing the full description (e.g., "studying physics at desk") to generate_action_pronunciatio, which validates input and invokes run_gpt_prompt_pronunciatio using an enhanced GPT prompt template featuring 12 diverse examples and strict instructions to output only 1-2 emojis. Three enforcement layers maintain quality: post-processing in run_gpt_prompt.py truncates excess emojis via regex extraction; validation in plan.py counts emojis and falls back to "😐" if invalid; and comprehensive error handling catches exceptions with detailed logging. Compatibility fixes include UTF-8 encoding for Windows, increased max_tokens to 20 for multi-byte emojis, and preservation of contextual details like parentheses in descriptions. The resulting emoji is integrated into movement JSON files, detected by file_watcher.py for WebSocket broadcast to the frontend's StatusSticker.tsx. Diagnostic logs monitor issues, defaulting to "😐" on failures. An attempted GPT-5 migration faced parameter incompatibilities (e.g., max_tokens vs. max_completion_tokens) and response parsing errors, leading to a rollback to GPT-4.x models while retaining compatibility shims in model_router.py for future upgrades, ensuring no regressions in emoji functionality.

## ✅ **6. YouTube-Live - Like Functionality**

### *BACKEND* upd. 2025-10-24

The backend now fully supports YouTube Live-style real-time simulation streaming with real-time status updates for frontend LIVE mode auto-activation.

**Core Features (Production-Ready):**
1. **Real-Time Updates** - FileWatcherService (`file_watcher.py`) monitors `movement/*.json` changes and broadcasts via WebSocket (`/ws/simulations/{sim_code}/movement`) with automatic coordinate conversion (tiles → pixels), auto-detecting the latest simulation on startup
2. **Step Access** - `/meta` endpoint for polling current/total steps with `is_latest` flag; `/step/{n}` for individual steps; `/steps` for paginated ranges
3. **Metadata** - `meta.json` updates after each step with `curr_time` timestamp, `current_step`, `total_steps`, and `is_latest` boolean (true when at live edge) for accurate LIVE detection
4. **Reliability** - Atomic file writes ensure immutability; ResilientService provides automatic fallbacks (filesystem → Supabase)

**Auto-LIVE Status Detection (New - Fixes Frontend Auto-Activation):**
- **Immediate Status Updates** (`background_tasks.py`): Sets status to `"running"` immediately when continuation starts, `"completed"` when finished
- **Smart Race Condition Handling** (`supabase_service.py`): Detects active simulations by comparing actual step count vs. completion markers; overcomes file timing issues during rapid continuation
- **New Response Flags**: `is_continuable` (can resume?), `is_latest` (at live edge?)
- **Result**: Frontend can auto-enable LIVE mode on page reload during active runs without any code changes

**Configuration:**
- `BROADCAST_DELAY=5.0` (seconds) - Anti-jitter broadcasts; set in environment variables
- Status detection threshold: 30 seconds for auto-detect "running" from file timestamps (tunable)

**Integration Points:**

### *Camera Drag Panning in Double Frontend*
Implemented v1.2 hybrid drag in `components/GameCanvas.tsx` (lines 1993-2053): Pointer events move player (inverted delta), camera follows. Google Maps-like for mouse/touch; clamps bounds; 60fps; portable via Phaser/Expo.

**Benefits:** Unified input; no snap-back; integrates with follow.

**Snippet:**
```typescript
// pointermove excerpt
if (this.isDragging && pointer.isDown) {
  const deltaX = pointer.x - dragLastX;
  const deltaY = pointer.y - dragLastY;
  player.x -= deltaX; player.y -= deltaY;
  const camera = this.cameras.main;
  const camWidth = camera.width / camera.zoom, camHeight = camera.height / camera.zoom;
  player.x = Math.max(camWidth / 2, Math.min(player.x, worldWidth - camWidth / 2));
  player.y = Math.max(camHeight / 2, Math.min(player.y, worldHeight - camHeight / 2));
  dragLastX = pointer.x; dragLastY = pointer.y;
  console.log(`🖱️ Dragging delta (${deltaX.toFixed(1)}, ${deltaY.toFixed(1)}) → player (${player.x.toFixed(0)}, ${player.y.toFixed(0)})`);
  this.input.setDefaultCursor('grabbing');
}
```
