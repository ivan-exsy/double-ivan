**Goal:**
Break down the project to distinct Frontend and Backend parts with DB and harden up the system for scalability:
- **Microservices separation** - Isolating ML/AI logic from business logic
- **Real-time communication** - WebSocket/realtime for agent movement
- **Database centralization** - Moving from file-based to proper DB
- **Authentication/Authorization** - Essential for production
- **DevOps pipeline** - Docker, CI/CD, proper deployment strategy

✅ **Scalability Benefits:**
- Independent scaling of ML compute vs web services
- Horizontal scaling of frontend clients
- Proper data persistence and consistency
- Environment separation (dev/staging/prod)

### **PART B: Production-Ready FastAPI Gateway**

**Architecture**: React Frontend ↔ FastAPI Gateway (port 8001) ↔ Supabase DB + Python Backend  
**Features**: REST APIs, WebSocket real-time, background tasks, comprehensive testing

#### **⚡ Quick Start**

```bash

.\venv\Scripts\Activate.ps1
cd api_gateway
uvicorn app.main:app --reload --port 8000

# Access docs: http://localhost:8000/docs
```

#### **📡 Core API Endpoints**

**Simulation Management:**
- `GET /api/simulations/` - List simulations
- `POST /api/simulations/{sim_code}/start` - Start simulation
- `GET /api/simulations/{sim_code}/status` - Current status
- `GET /api/simulations/{sim_code}/personas` - Agent positions

**Real-time Data:**
- `GET /api/simulations/{sim_code}/step/{step}` - Step data
- `GET /api/simulations/{sim_code}/steps` - Range queries

**System Monitoring:**
- `GET /api/file-watcher/status` - File sync health
- `GET /api/simulations/tasks/{task_id}` - Background tasks

#### **🔌 WebSocket Channels**

- `ws://localhost:8001/ws/simulations/{sim_code}/movement` - Agent movement
- `ws://localhost:8001/ws/simulations/{sim_code}/chat` - Conversations  
- `ws://localhost:8001/ws/health` - Connection monitoring

### **PART C: Production-Ready Backend Integration ✅**

**Architecture**: FastAPI Gateway (port 8001) → Python Backend → Supabase DB  
**Data Flow**: Python writes JSON → File Watcher → Database sync → WebSocket broadcast

#### **📡 Key API Endpoints**

**User Management:**
- `POST /api/users/create-sprite` - Create avatars
- `POST /api/simulations/main/join` - Join simulation (25-user limit)

**Real-time Data:**
- `GET /api/simulations/main/status` - Current simulation state
- `WebSocket ws://localhost:8001/ws/simulations/main/movement` - Live updates

**File Watcher Control:**
- `GET /api/file-watcher/status` - Monitor sync health
- `POST /api/file-watcher/set-active-simulation` - Target specific simulation

#### **🔄 Dual-Recording System**

**Local Files** → **Supabase Database**
- Python backend writes `movement/{step}.json`
- File watcher syncs to `double.personas_coords` table
- WebSocket broadcasts real-time updates
- 500ms detection latency

#### **⚡ Quick Start for Frontend**

```bash
# Test connectivity
curl http://localhost:8001/docs

# Create user avatar
curl -X POST http://localhost:8001/api/users/create-sprite \
  -H "Content-Type: application/json" \
  -d '{"user_id":"user123","name":"Alice","personality":"explorer"}'

# Join main simulation
curl -X POST http://localhost:8001/api/simulations/main/join \
  -H "Content-Type: application/json" \
  -d '{"user_id":"user123","sprite_name":"Alice"}'
```

**Frontend Integration:**
- **REST API**: All endpoints at `localhost:8001/api/*`
- **WebSocket**: `ws://localhost:8001/ws/simulations/main/movement`
- **Documentation**: `localhost:8001/docs`
- **Database**: Direct Supabase queries for historical data
