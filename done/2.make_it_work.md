## **Comprehensive Architecture Optimization Plan**

### *Executive Summary* {#executive-summary}

After analyzing the current file-based memory system and 50+ GPT function calls per simulation step, we've identified that **architectural optimization is critical** beyond simple model swaps. The current system uses JSON file storage, keyword-based memory retrieval, and sequential cognitive processing that leads to significant inefficiencies.

**Current System Analysis:**
- **Memory Storage**: JSON files (`nodes.json`, `embeddings.json`) with keyword-based indexing
- **Retrieval Method**: In-memory cosine similarity calculations, no vector database  
- **API Calls**: 30+ different `run_gpt_prompt_*` functions per simulation step
- **State Management**: Scattered across multiple JSON files per agent

**Target Outcomes:**
- **Cost reduction**: From ~$2/day → ~$0.23/day for 25 agents
- **Performance improvement**: Sub-100ms memory retrieval with pgvector HNSW indexing  
- **Scalability**: Support for 100+ agents with layered memory architecture
- **Maintainability**: Consolidated state management and reduced prompt complexity

**Staged Approach:**
Each stage leaves the project **fully functional for testing** while incrementally adding optimization capabilities. The plan addresses the gap between current file-based system and proposed vector database architecture through careful migration and validation.
