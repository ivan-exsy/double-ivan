# Supabase-First Architecture Reference

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────────┐
│                    SUPABASE (Single SOT)                         │
├─────────────────────────────────────────────────────────────────┤
│  double.simulations      │ Simulation metadata + state          │
│  double.personas         │ Persona definitions                  │
│  double.dbl_memory       │ All memories (pgvector 768-d)        │
│  double.persona_scratch  │ Transient state (action, path, plan) │
│  double.personas_coords  │ Position history                     │
│  double.maze_tiles       │ World collision/semantic data        │
│  double.carried_objects  │ Objects being carried                │
│  double.asset_*          │ Asset assignments & translations     │
└─────────────────────────────────────────────────────────────────┘
         ↑ Realtime subscriptions
┌────────┴────────┐     ┌─────────────────┐
│ Python Backend  │←───→│ Frontend        │
│ (reverie.py)    │     │ (Next.js/Phaser)│
└─────────────────┘     └─────────────────┘
```

**Schema Rule**: Tables in `double.` schema, all RPCs in `public.` schema (Supabase PostgREST requirement).

## 2. Coordinate/Position SOT

### Tables
| Table | Purpose |
|-------|---------|
| `personas_coords` | Position history (INSERT planned, UPDATE actual) |
| `grid_deltas` | Spatial change tracking |

### Key RPCs
| RPC | Purpose |
|-----|---------|
| `update_avatar_position_dev(sim_name, persona_name, x, y, step)` | Insert/update position |
| `get_latest_positions(sim_name)` | All persona positions for simulation |
| `get_latest_persona_position(sim_name, persona_name)` | Single persona position |
| `get_step_positions(sim_name, step)` | Positions at specific step (playback) |
| `get_tile_context(maze_name, x, y)` | AI context for tile |

### Data Flow
```
Step N:
1. Backend INSERT → personas_coords (planned position)
2. Frontend A* pathfinding + animation
3. Frontend POST /observations (actual_pos)
4. Backend UPDATE → personas_coords (actual position)
5. scratch.last_actual_pos updated (cache)

Step N+1:
6. Position read: scratch cache → Supabase → JSON fallback
```

### Python Class
**`SpatialCoordClient`** (`double_memory_client.py`)
- `update_position()`, `batch_update_positions()`, `get_tile_context()`
- `bootstrap_simulation()`, `ensure_simulation()`, `ensure_persona()`

### Frontend Hook
**`useSupabaseCoords`** (`hooks/useSupabaseCoords.ts`)
- Subscribes to `double.personas_coords` INSERT + UPDATE events
- Resolves `sim_code` → UUID via `get_simulation_id_by_name`
- Console logs: `📍 [planned]` for INSERT, `✅ [actual]` for UPDATE

## 4. Simulation Management

### Tables
| Column/Table | Purpose |
|--------------|---------|
| `simulations.parent_simulation_id` | Fork parent (NULL for baselines) |
| `simulations.is_baseline` | Forkable flag |
| `simulations.fork_depth` | 0=baseline, 1=direct fork |
| `simulation_persona_state` | Per-sim persona scratch + spatial memory |

### Key RPCs
| RPC | Purpose |
|-----|---------|
| `bootstrap_simulation(sim_code, maze_name, persona_names)` | Create sim + personas + links |
| `fork_simulation(baseline, new_name, copy_memories, copy_coords)` | Full fork with isolation |
| `mark_as_baseline(sim_name)` | Enable forking |
| `list_simulation_forks(baseline_name)` | List forks |
| `get_simulation_metadata(sim_name)` | curr_time, total_steps, status |
| `update_simulation_metadata(...)` | Update sim state |

### Fork Architecture
```
BASELINE (is_baseline=TRUE)
    │
    ├── fork_simulation() ──► FORK A (fork_depth=1, own maze_instance, own memories)
    │
    └── fork_simulation() ──► FORK B (fork_depth=1, independent evolution)
```

Each fork has isolated: `dbl_memory.simulation_id`, `maze_instance_tiles`, `personas_coords`.

## 10. Troubleshooting

### Memory writes failing silently
1. Check `MEMORY_PRIMARY` env var is set
2. Look for console output: `📝 Phase 10.1: MEMORY_PRIMARY = 'supabase'`
3. Check for duplicate key violations (node_id generation)
4. Verify `simulation_id` propagation via `_propagate_simulation_id_to_memory_stores()`

### pgvector retrieval slow
Run HNSW index optimization:
```sql
-- See scripts/optimize_pgvector_now.sql
```
Expected: 800-1200ms → 77ms (~12x improvement)

### Maze tiles missing sector/arena
Re-run migration with `.strip()` fix:
```powershell
python scripts/migrate_maze_to_supabase.py --maze-name the_ville
```

### Frontend stuck in "loading"
- Check `useSimulation.ts` init logic
- Verify RPC returns `total_steps` (not undefined)
- Running sims with unknown steps should proceed, not early-exit

### Realtime not updating
- Verify table is published: `ALTER PUBLICATION supabase_realtime ADD TABLE double.personas_coords`
- Check subscription event type: `'*'` for INSERT+UPDATE, not just `'INSERT'`
- Verify `sim_code` filter matches exactly

### Fork isolation broken
- Verify `simulation_id` column exists on `dbl_memory` and `dbl_semantic_facts`
- Check `dbl_store_memory_dev` extracts `simulation_id` from JSONB payload
- Confirm `_propagate_simulation_id_to_memory_stores()` called after bootstrap

## *Fixing Issues*

### Fix 1: Memory writes falling back to JSON
**Cause**: `MEMORY_PRIMARY='supabase'` set but writes failing silently.
**Fix**: Added startup logging, enhanced error visibility in `_write_to_supabase_with_retry()`.

### Fix 2: Duplicate key violations
**Cause**: Empty `node_id`, missing `simulation_id` in transforms.
**Fix**: 
- Added `_generate_node_id()` method
- Added `simulation_id` to all transforms
- Updated `dbl_store_memory_dev` with `ON CONFLICT ... DO UPDATE`

### Fix 3: pgvector slow (800-1200ms)
**Fix**: HNSW index optimization → 77ms avg, 92ms P95.

### Fix 4: Frontend stuck loading running sims
**Cause**: `totalSteps === 0` treated as "init sim" even when running.
**Fix**: Changed detection to `totalSteps === 0 && !status.running`, added Supabase RPC fallback for `total_steps`.

### Fix 5: Frontend not enforcing 6 tiles/step speed cap
**Cause**: `useTurnBasedFeedback.ts` only validated violations post-hoc; `AnimationManager.ts` didn't truncate paths exceeding limit, causing teleportation artifacts.
**Fix**: 
- Added path truncation in `AnimationManager.ts` per Phaser Docs §4: `if (pathTiles.length > MAX_TILES_PER_STEP + 1)`
- Store `remaining_path` in `window.__remainingPaths` for multi-step continuation
- Include `remaining_path` in `movement_report` observations for backend pickup
- Updated `MovementReport` interface in `observationManager.ts`

### Fix 6: Frontend replay shows static sprites (no movement animation)
**Cause**: `personas_coords` table stored only `x, y, description`; `get_step_positions` RPC returned no `target_zone`/`path` data. Frontend received `target_zone: null` → fallback 0-duration tweens → no visual movement.
**Fix**:
- Added `movement JSONB` column to `personas_coords` table
- Updated `get_step_positions` and `get_all_step_positions` RPCs to return `movement` column
- Updated `update_avatar_position_dev` RPC to accept `p_movement` param
- Modified `SpatialCoordClient.update_position()` to accept `movement` dict
- Modified `batch_update_positions()` to pass movement data per persona
- Updated `reverie.py` SOT sync to extract and persist `target_zone`, `path`, `speed_multiplier`, `facing`, `partial_state`

### Fix 7: Headless validation bugs causing step failures
**Cause**: `headless_visualization.py` had two bugs: (1) `actual_pos_pixels referenced before assignment` when Priority 1 position source succeeded; (2) `'<' not supported between dict and int` when `target_zone` contained malformed nested data.
**Fix**:
- Added `ENABLE_POSITION_VALIDATION` flag (default: false) — validation is optional QA, not required by frontend
- Position validation now skipped by default; execution + observation extraction remain active
- Fixed Bug 1: Initialize `actual_pos_pixels = None` before conditional assignment
- Fixed Bug 2: Added type checking and try/catch for `target_zone` numeric extraction
- Headless execution (`__executeMovementsForStep`) and observation extraction (`__headlessObservations`) preserved for unattended simulation generation

### Fix 8: Supabase-first architecture verification (20260109-3)
**Validation**: 5-step simulation run confirmed Supabase SOT stable post-fixes 6-7.
**Results**:
- Positions: 20/20 synced to `personas_coords` with movement JSONB (target_zone, path, speed_multiplier)
- Memory: pgvector retrieval 100% hit rate via `dbl_retrieve_with_rir`
- Realtime: 4/4 personas bootstrapped, INSERT+UPDATE events working
- Chat: 1 session (7 exchanges), metadata persisted correctly
- Progression: 90% logical (family morning routine), 80% movements in-zone
- Headless: Execution + observation extraction functional; validation disabled by default
- Frontend: Updated `lib/api.ts` and `hooks/usePlayback.ts` to extract `movement.target_zone` from RPC responses (Fix 6 schema change)

### Fix 9: RPC Regression - Missing movement column (20260109-4)
**Cause**: Migrations `20260120000001_phase10_memory_flip.sql` and `20260120000002_phase10_fix_updated_at.sql` accidentally overwrote the `get_step_positions` and `get_all_step_positions` RPCs, removing the `movement JSONB` column that was added in Fix 6 (`20260110000015`).
**Symptoms**: Frontend replay received `target_zone: null` → fallback to 0-duration tweens → static sprites after step 0.
**Fix**:
- Created `20260125000001_phase10_fix_movement_rpc.sql` to restore `movement` column to both position RPCs
- Verified RPC returns: `['persona_name', 'x', 'y', 'description', 'movement']`
- Movement JSONB contains: `path`, `facing`, `target_zone`, `pronunciatio`, `partial_state`, `speed_multiplier`, `estimated_duration`
**Prevention**: Future migrations should not use `CREATE OR REPLACE` for RPCs without checking existing return schema

### Fix 10: Running sims stuck in "Loading..." (status field mismatch)
**Cause**: Frontend expected `status.running: boolean` from `getStatus()` API, but backend only returns `status: string` ('running'|'stopped'|...). The `running` boolean was never implemented—phantom field in TypeScript interface. Result: `status.running === undefined` → `!status.running` truthy → running sims detected as "init sim" → forced stopped state.
**Fix**:
- Removed phantom `running: boolean` from `lib/api.ts` interface (confirmed with backend: field never existed)
- Added `const isRunning = status.status === 'running'` in `useSimulation.ts`
- Updated init detection: `totalSteps === 0 && !isRunning` (was `!status.running`)
- Added mock `rpc`, `channel`, `removeChannel` methods to `MockSupabase` interface in `lib/supabase.ts` (fixes build error when Supabase not configured)

### Fix 11: Frontend no re-routing on playback
**Cause**: `AnimationManager.ts` ignored backend `path` arrays, recomputing A* paths then truncating to 7 waypoints—causing slow crawls and position bouncing.
**Fix**:
- Prioritize backend `path` when `path.length > 1`, fallback to A* only when no path exists
- Removed arbitrary 7-waypoint truncation
- Scaled playback timeouts to match actual animation duration (60s instead of 5s)
- Force-reposition sprites drifting >5 tiles

### Fix 12: Unified conversation architecture
**Cause**: Every perception triggered `generate_decide_to_talk()` LLM calls (~100+ per step with 3 agents).
**Fix**: Added `OBSERVATION_PRIMARY` + `ENABLE_HEADLESS_VALIDATION` flags:
| OBSERVATION_PRIMARY | ENABLE_HEADLESS_VALIDATION | Conversation Trigger |
|---------------------|---------------------------|----------------------|
| `true` (default) | `true` | Observation path only (saves LLM calls) |
| `true` | `false` | Plan path (fallback, no frontend) |
| `false` | any | Plan path (legacy) |

### Fix 13: Supabase step SOT with JSON fallback
**Data Flow**:
- SIMULATION: Supabase write (PRIMARY) → JSON write (BACKUP, if not skipped)
- API RETRIEVAL: Supabase RPC (PRIMARY) → JSON file (FALLBACK)

**New Env Vars**:
| Variable | Default | Description |
|----------|---------|-------------|
| `USE_SUPABASE_STEP_SOT` | `true` | API Gateway uses Supabase for step retrieval |
| `SKIP_MOVEMENT_JSON_WRITE` | `false` | Skip `movement/{step}.json` writes |
| `SKIP_ENV_JSON_WRITE` | `false` | Skip `environment/{step}.json` writes |
| `SUPABASE_COORD_REQUIRED` | `false` | Fail step if Supabase write fails (strict mode) |

### Fix 14: Frontend tile→pixel conversion for direct RPC
**Cause**: Direct Supabase RPC returns tile coords, frontend expects pixels.
**Fix** (`usePlayback.ts`, `lib/api.ts`):
```typescript
const TILE_SIZE = 32, TILE_OFFSET = 16;
const toPixel = (tile: number) => tile * TILE_SIZE + TILE_OFFSET;
// Convert x, y, path waypoints, target_zone bounds
```

### Fix 15: Frontend column name handling
**Cause**: RPC returns `persona_name`/`movement_jsonb`, code read `row.name`/`row.movement`.
**Fix**: `row.name || row.persona_name`, `row.movement || row.movement_jsonb`, compute timestamps from `baseTimestamp + step × 60000ms`.

### Fix 16: Sprite position initialization & step 0 animation
**Cause**: Sprite at END position → animation has nowhere to go; step 0 processed with stale HTTP data.
**Fix**:
- Use `path[0]` for initial sprite position, `path[-1]` for animation target
- Added `playbackJustStartedRef` flag to skip first render (wait for RPC data)
- Reset `lastProcessedStepRef = -1` on playback start to allow step 0 animation
